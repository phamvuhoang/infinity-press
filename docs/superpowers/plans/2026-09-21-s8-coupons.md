# S8 Coupons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reader enters a promotion code on checkout and pays less — or nothing, in which case the order completes at once and the reader lands in the reader — while an operator creates, scopes, limits, and retires those codes from `/admin/coupons` without a deployment.

**Architecture:** A code applies to an existing `pending` order, not to a new draft or quote lifecycle. `apply_coupon_to_order` is a `security definer` RPC that locks the coupon row, reserves a redemption, rewrites the order's `subtotal_minor`/`discount_minor`/`total_minor` snapshot and the pending `payments` amount, and — when the resulting total is zero — completes the order and grants the entitlement in the same transaction. Because the reservation is taken at apply time, neither `apply_payment_event` nor `confirm_manual_payment` ever has to refuse an order over a coupon; they only flip a row that already exists. The discount arithmetic lives once in `lib/commerce/coupon.ts` and once in SQL, driven by the same table of cases in Vitest and pgTAP, the way `lib/commerce/order-state.ts` and `supabase/tests/018_ebook_orders.sql` already mirror each other.

**Tech Stack:** Next.js 16 App Router, React Server Components, Server Actions, Supabase (Postgres, Auth, RLS, `security definer` RPCs), TypeScript, Zod, Vitest, pgTAP, Playwright, Tailwind.

**Spec:** `docs/superpowers/specs/2026-09-21-s8-coupons-design.md`

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before changing Next.js code. This is not the Next.js in your training data.
- Every protected page and every Server Action calls `requireUser()` or `requireAdmin()` itself. A layout is never the only authorization control.
- Customer routes live under `/{locale}` with locales `vi` and `en`. `/admin` has no locale prefix.
- Never expose `SUPABASE_SERVICE_ROLE_KEY` to browser code. A service-role client is created only after an admin gate passes.
- Applied migrations are never edited. Every schema change is a new file in `supabase/migrations/` named `YYYYMMDDHHMMSS_<slug>.sql`, with a matching pgTAP file in `supabase/tests/` and an update to `lib/supabase/database.types.ts`.
- Every new table, policy, and RPC gets pgTAP tests including cross-user negative cases.
- Database functions that need elevated access to protected tables carry `security definer` with `set search_path = ''` and fully qualified object names. Pure computational helpers that read no table do not.
- Entitlements are granted only by the existing authenticated database functions, or — for the zero-total case this plan adds — by `apply_coupon_to_order`, which is the one new function permitted to insert an entitlement, and does so with `source_type = 'free_order'` and `source_order_id` set, exactly as `acquire_free_ebook` does.
- Amounts are integer minor units with an ISO 4217 currency. Never floating point. The discount is computed with integer arithmetic on both sides.
- Preserve request IDs in server errors and operational logs: `getRequestId(await headers())`.
- Reader-facing copy exists in both `lib/i18n/dictionaries/vi.json` and `lib/i18n/dictionaries/en.json`. Admin copy is English only, matching the existing admin pages.
- One order carries at most one coupon. A discount is never applied automatically — only when a reader enters a code.
- Run `npm run check` after every task. Run `npm run db:reset` and `npm run db:test` after every task that adds a migration. Run `npm run check:full` at the end. `npm run check`'s `test:unit` step needs the local Supabase stack **down** (`supabase stop`) — the `scripts/ebook.ts` unit test fails whenever a stack is up, and that failure is not a regression you introduced.
- New Postgres error codes introduced by this plan, documented in each migration's header comment. `EB001`–`EB017` and `EB020`–`EB023` are already taken; this plan continues at `EB024`:
  - `EB024` — `apply_coupon_to_order` / `remove_coupon_from_order`: the order is not the caller's own `pending` order, or already carries a coupon (apply), or a bank transfer has already been reported against it.
  - `EB025` — `admin_update_coupon`: the kind or value of a coupon that already has a reservation or a redemption cannot change.

## Deviations from the spec, and why

Two, both flagged here rather than made silently. Neither changes what a reader or an operator sees.

1. **Coupon rejections are returned as a value, not raised.** Spec §5.5 wants failed attempts counted per profile so a guessable code cannot be brute-forced. PostgREST runs each RPC in one transaction, and a `raise` rolls that transaction back — including the very row that recorded the failed attempt, which would leave the counter permanently at zero and the rate limit decorative. So `apply_coupon_to_order` returns a `rejection` column (`null`, `'invalid'`, or `'rate_limited'`) for every coupon-validity failure, and its write of the attempt counter commits. Spec §4's real requirement is preserved and strengthened: every rejection carries the *same* `rejection` value and the same reader-facing message. The function was originally planned to also return a `detail` column naming the specific reason (unknown code, inactive, expired, and so on) for the Server Action to log, but a value returned to `authenticated` is a value `authenticated` can read — a `detail` column would have handed a guesser the exact discriminator the uniform `rejection` value exists to hide, making it a code oracle in its own right. `detail` was dropped from the return type before this shipped. Every rejection reason instead goes out with `raise log` (Postgres forwards `NOTICE`/`INFO`/`WARNING` to the calling client, but never `LOG`), naming the order id, the profile id, and the reason; nothing about *why* a code was rejected ever reaches the response or the application log — see `docs/runbooks/coupons.md` §6 for how an operator reads it back out of the Postgres log. Refusals about the **order** (not yours, not pending, already couponed, transfer already reported) still `raise` `EB024`: they are not a code oracle — the caller already knows which order they opened — and there is nothing to count for them.
2. **`orders` carries a `coupon_code` snapshot beside `coupon_id`.** Spec §5.2 makes `coupons` unreadable through the Data API so codes cannot be enumerated, and spec §7.1 asks checkout to show the applied code. A reader therefore cannot resolve `coupon_id` back to a code. The code is snapshotted onto the order, which also satisfies the exit criterion that no completed order can lose or change its coupon.

One clarification, not a deviation: spec §5.2 says `coupons` is "readable by nobody through the Data API" while spec §8 asks for a pgTAP case proving "a non-admin cannot read `coupons`". This plan takes the stricter reading — **no** select policy on `coupons` or `coupon_books` at all — and gives the admin screens `security definer` reader RPCs instead. The pgTAP case then passes for the non-admin *and* for the admin, and no role can enumerate codes by querying the table.

```ts
// The discount rules, written once (S8 spec 6). apply_coupon_to_order implements the same rules in
// SQL and supabase/tests/036_s8_coupon_rpcs.sql runs the same cases, the way lib/commerce/
// order-state.ts and supabase/tests/018_ebook_orders.sql already mirror each other. This module
// reads nothing and decides nothing about eligibility; it is arithmetic and a code format.
export type CouponKind = "percent" | "fixed";

export type CouponRule =
  | { kind: "percent"; percentOff: number }
  | { kind: "fixed"; amountOffMinor: number; currency: string };

export type OrderAmount = { subtotalMinor: number; currency: string };

// A code is read off a screen, a chat message, or a slip of paper and typed back in, so the
// alphabet stays to upper-case ASCII letters, digits, and the hyphen. The same pattern is a CHECK
// constraint on coupons.code, so a code that cannot be typed here cannot be created there either.
export const COUPON_CODE_PATTERN = /^[A-Z0-9][A-Z0-9-]{1,30}[A-Z0-9]$/;

// Readers paste codes with stray spaces and in whatever case they were written. Normalization is
// applied on write (the admin editor) and on read (the checkout field), so the two always meet.
export function normalizeCouponCode(raw: string): string {
  return raw.replace(/\s+/g, "").toUpperCase();
}

export function isCouponCode(value: string): boolean {
  return COUPON_CODE_PATTERN.test(value);
}

export function computeDiscountMinor(coupon: CouponRule, order: OrderAmount): number {
  const raw =
    coupon.kind === "percent"
      ? // Integer maths, floored: a discount never rounds up into the house's money.
        Math.floor((order.subtotalMinor * coupon.percentOff) / 100)
      : fixedAmount(coupon, order);
  // Clamped, so a fixed amount larger than the price yields a zero total rather than a negative one.
  return Math.min(Math.max(raw, 0), Math.max(order.subtotalMinor, 0));
}

function fixedAmount(coupon: { amountOffMinor: number; currency: string }, order: OrderAmount): number {
  // Unreachable through apply_coupon_to_order, which rejects a currency mismatch as an invalid
  // coupon before it computes anything. It throws rather than converting because there is no
  // conversion rate in this system, and silently treating 500 USD cents as 500 VND would be a
  // pricing error nobody would see until the money was gone.
  if (coupon.currency !== order.currency) {
    throw new Error(`computeDiscountMinor: coupon currency ${coupon.currency} does not match order currency ${order.currency}`);
  }
  return coupon.amountOffMinor;
}
```

```sql
--
-- No new error codes. The RPCs that raise EB024/EB025 arrive in 20260923120000 and 20260923140000.
--
-- Three tables and four order columns. The order columns are the load-bearing part: an order's
-- money is a snapshot, and after this migration that snapshot is three numbers instead of one,
-- tied together by a CHECK so no writer can leave them disagreeing.
create table public.coupons (
  id uuid primary key default gen_random_uuid(),
  -- Stored upper-case; normalized on write by admin_create_coupon and matched upper-case by
  -- apply_coupon_to_order. The pattern is lib/commerce/coupon.ts's COUPON_CODE_PATTERN.
  code text not null unique check (code ~ '^[A-Z0-9][A-Z0-9-]{1,30}[A-Z0-9]$'),
  kind text not null check (kind in ('percent', 'fixed')),
  percent_off int check (percent_off between 1 and 100),
  amount_off_minor bigint check (amount_off_minor > 0),
  currency text check (currency ~ '^[A-Z]{3}$'),
  starts_at timestamptz,
  ends_at timestamptz,
  active boolean not null default true,
  max_redemptions int check (max_redemptions > 0),
  max_redemptions_per_profile int not null default 1 check (max_redemptions_per_profile > 0),
  note text check (note is null or char_length(note) <= 500),
  created_by uuid references public.profiles(id),
  created_at timestamptz not null default now(),
  -- Each kind carries its own evidence and nothing else, so no row can be half a percentage and
  -- half an amount. The else branch fails closed for any kind this CASE does not yet know about,
  -- the way entitlements_source_consistency does.
  constraint coupons_kind_consistency check (
    case kind
      when 'percent' then percent_off is not null and amount_off_minor is null and currency is null
      when 'fixed' then amount_off_minor is not null and currency is not null and percent_off is null
      else false
    end

-- "one coupon per order" a schema rule rather than a convention.

);

-- the coupon row lock, on every application.
create index coupon_redemptions_coupon_idx on public.coupon_redemptions (coupon_id, profile_id);

-- The order snapshot. Backfill before the constraints, the ordering discipline
-- 20260922110000_order_reference_code.sql established: every existing order has no discount, so
-- its subtotal is its total.

  add column subtotal_minor bigint,
  add column discount_minor bigint not null default 0,
  add column coupon_id uuid references public.coupons(id),
  add column coupon_code text;

alter table public.orders
  alter column subtotal_minor set not null,
```

```sql
-- S8: the per-profile failed-attempt quota for coupon codes (spec 5.5), reusing the fixed-window
-- shape 20260916140000_s5_analytics_intake_quota.sql established.
--
-- No new error codes.
--
-- Why a code needs this at all: a code is short, guessable, and a wrong one is an oracle. The
-- counter is per profile because apply_coupon_to_order is only reachable by a signed-in reader on
-- their own order, so a profile - not an IP address - is the actor. No IP address, or anything
-- derived from one, is stored here.
--
-- One row per profile that has ever entered a wrong code; nothing else is written, so the table
-- stays small without a cleanup job.
create table public.coupon_attempts (
  profile_id uuid primary key references public.profiles(id) on delete cascade,
  window_start timestamptz not null default now(),
  failure_count integer not null default 0 check (failure_count >= 0)
);

alter table public.coupon_attempts enable row level security;
revoke all on public.coupon_attempts from public, anon, authenticated, service_role;

-- The limit and the window. Ten wrong codes in ten minutes is far more than a reader retyping a
-- code from a chat message, and far less than a useful search of the code space.
create function public.coupon_attempts_exhausted(p_profile_id uuid)
returns boolean
language sql
security definer
set search_path = ''
stable
as $$
  select coalesce(
    (select a.failure_count >= 10 and a.window_start > now() - interval '10 minutes'
     from public.coupon_attempts a where a.profile_id = p_profile_id),
    false
  );
$$;

-- Called on a REJECTED application, never on a successful one, and never from a code path that is
-- about to raise: an exception would roll this write back with the rest of the transaction, which
-- is exactly why apply_coupon_to_order returns its rejection as a value instead of raising it.
create function public.record_coupon_failure(p_profile_id uuid)
returns void
language plpgsql
security definer
set search_path = ''
as $$
begin
  insert into public.coupon_attempts as a (profile_id, window_start, failure_count)
  values (p_profile_id, now(), 1)
  on conflict (profile_id) do update set
    window_start = case when a.window_start <= now() - interval '10 minutes' then now() else a.window_start end,
    failure_count = case when a.window_start <= now() - interval '10 minutes' then 1 else a.failure_count + 1 end;
end;
$$;

revoke execute on function public.coupon_attempts_exhausted(uuid) from public, anon, authenticated;
revoke execute on function public.record_coupon_failure(uuid) from public, anon, authenticated;
```

- [ ] **Step 1: Write the migration**

Create `supabase/migrations/20260923120000_s8_coupon_rpcs.sql`:

```sql
-- S8: the reader's two coupon RPCs (spec 5.4).
--
-- New error code, continuing the EB0xx series (EB023 is taken by 20260922130000):
--   EB024 - apply_coupon_to_order / remove_coupon_from_order: the order is not the caller's own
--           pending order, already carries a coupon (apply), or has a reported bank transfer.
--
-- Why a rejected CODE is returned rather than raised. PostgREST wraps an RPC in one transaction, so
-- a raise rolls back everything the call wrote - including record_coupon_failure, which is the
-- entire mechanism spec 5.5 asks for. The counter would sit at zero forever and the rate limit
-- would be decoration. So a coupon-validity failure comes back as `rejection = 'invalid'` (or
-- 'rate_limited'), the transaction commits, and the counter moves. Every such rejection carries the
-- SAME value: unknown, expired, not yet started, inactive, wrong book, exhausted, per-profile limit
-- reached, and wrong currency are indistinguishable to the caller. The discriminating text comes
-- back in `detail`, which the Server Action writes to the server log with the request ID and never
-- into a response.
--
-- Refusals about the ORDER still raise EB024. They are not a code oracle - the caller already knows
-- which order they opened - and there is nothing to count for them.
create function public.apply_coupon_to_order(p_order_id uuid, p_code text)
returns table (
  subtotal_minor bigint,
  discount_minor bigint,
  total_minor bigint,
  order_status public.order_status,
  entitlement_id uuid,
  rejection text,
  detail text
)
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_profile_id uuid;
  v_code text;
  v_order record;
  v_coupon record;
  v_discount bigint;
  v_total bigint;
  v_used int;
  v_used_by_profile int;
  v_book_id uuid;
  v_entitlement_id uuid;
begin
  select p.id into v_profile_id from public.profiles p where p.auth_user_id = auth.uid();
  if v_profile_id is null then
    raise exception 'apply_coupon_to_order: no profile for the current session' using errcode = 'P0002';
  end if;

  -- Lock the order first, so two applications on one order serialize, and so the coupon row lock
  -- below is always taken second. One lock order everywhere is what keeps this function and
  -- create_ebook_order from deadlocking against each other.
  select o.id, o.profile_id, o.status, o.currency, o.subtotal_minor, o.coupon_id
  into v_order
  from public.orders o
  where o.id = p_order_id and o.profile_id = v_profile_id
  for update;

  -- Another reader's order is indistinguishable from a missing one.
  if v_order.id is null or v_order.status <> 'pending' or v_order.coupon_id is not null then
    raise exception 'apply_coupon_to_order: order % is not an uncouponed pending order of the caller', p_order_id
      using errcode = 'EB024';
  end if;

  -- A reader who has already told us they transferred has sent a specific amount with a specific
  -- reference; moving the total underneath that report would leave the admin reconciling a payment
  -- against a number nobody ever saw. The code can still be applied before the transfer, which is
  -- when a reader would actually use one.
  if exists (select 1 from public.manual_transfer_claims c where c.order_id = p_order_id) then
    raise exception 'apply_coupon_to_order: order % already has a reported transfer', p_order_id
      using errcode = 'EB024';
  end if;

  if public.coupon_attempts_exhausted(v_profile_id) then
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'rate_limited'::text, 'too many failed attempts'::text;
    return;
  end if;

  -- Normalization mirrors lib/commerce/coupon.ts normalizeCouponCode exactly.
  v_code := upper(regexp_replace(coalesce(p_code, ''), '\s', '', 'g'));

  select c.* into v_coupon
  from public.coupons c
  where c.code = v_code
  for update;

  if v_coupon.id is null then
    perform public.record_coupon_failure(v_profile_id);
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'invalid'::text, 'unknown code'::text;
    return;
  end if;

  if not v_coupon.active then
    perform public.record_coupon_failure(v_profile_id);
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'invalid'::text, 'inactive'::text;
    return;
  end if;

  if v_coupon.starts_at is not null and v_coupon.starts_at > now() then
    perform public.record_coupon_failure(v_profile_id);
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'invalid'::text, 'not yet started'::text;
    return;
  end if;

  if v_coupon.ends_at is not null and v_coupon.ends_at <= now() then
    perform public.record_coupon_failure(v_profile_id);
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'invalid'::text, 'expired'::text;
    return;
  end if;

  select oi.book_id into v_book_id from public.order_items oi where oi.order_id = p_order_id limit 1;

  -- No coupon_books rows at all means every book (spec 5.2).
  if exists (select 1 from public.coupon_books cb where cb.coupon_id = v_coupon.id)
     and not exists (select 1 from public.coupon_books cb where cb.coupon_id = v_coupon.id and cb.book_id = v_book_id) then
    perform public.record_coupon_failure(v_profile_id);
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'invalid'::text, 'wrong book'::text;
    return;
  end if;

  if v_coupon.kind = 'fixed' and v_coupon.currency <> v_order.currency then
    perform public.record_coupon_failure(v_profile_id);
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'invalid'::text, 'currency mismatch'::text;
    return;
  end if;

  -- Both limits are counted under the coupon row lock taken above, which is what makes "the last
  -- remaining use goes to exactly one of two concurrent readers" true: the second session blocks on
  -- the lock until the first has inserted its reservation, then counts it.
  select count(*) into v_used from public.coupon_redemptions r where r.coupon_id = v_coupon.id;
  if v_coupon.max_redemptions is not null and v_used >= v_coupon.max_redemptions then
    perform public.record_coupon_failure(v_profile_id);
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'invalid'::text, 'exhausted'::text;
    return;
  end if;

  select count(*) into v_used_by_profile
  from public.coupon_redemptions r where r.coupon_id = v_coupon.id and r.profile_id = v_profile_id;
  if v_used_by_profile >= v_coupon.max_redemptions_per_profile then
    perform public.record_coupon_failure(v_profile_id);
    return query select v_order.subtotal_minor, 0::bigint, v_order.subtotal_minor, v_order.status,
                        null::uuid, 'invalid'::text, 'per-profile limit reached'::text;
    return;
  end if;

  -- The same arithmetic as lib/commerce/coupon.ts computeDiscountMinor: floored, then clamped.
  -- Integer division in Postgres truncates toward zero, which on non-negative operands is floor.
  v_discount := case v_coupon.kind
    when 'percent' then (v_order.subtotal_minor * v_coupon.percent_off) / 100
    else v_coupon.amount_off_minor
  end;
  v_discount := least(greatest(v_discount, 0), v_order.subtotal_minor);
  v_total := v_order.subtotal_minor - v_discount;

  update public.orders o
  set coupon_id = v_coupon.id, coupon_code = v_coupon.code, discount_minor = v_discount, total_minor = v_total
  where o.id = p_order_id;

  insert into public.coupon_redemptions (coupon_id, order_id, profile_id, discount_minor, status)
  values (v_coupon.id, p_order_id, v_profile_id, v_discount, 'reserved');

  -- Every code that changed an order total is audited (spec 2). actor_profile_id is the reader
  -- here, not an admin: they are the actor.
  insert into public.audit_logs (actor_profile_id, action, entity_type, entity_id, reason, metadata)
  values (v_profile_id, 'coupon.applied', 'orders', p_order_id, null,
          jsonb_build_object('coupon_id', v_coupon.id, 'code', v_coupon.code,
                             'discount_minor', v_discount, 'total_minor', v_total));

  if v_total > 0 then
    update public.payments pay
    set amount_minor = v_total
    where pay.order_id = p_order_id and pay.status = 'pending';

    return query select v_order.subtotal_minor, v_discount, v_total, v_order.status,
                        null::uuid, null::text, null::text;
    return;
  end if;

  -- Zero total: the order completes here, in this transaction (spec 4). There is nothing to pay,
  -- so the pending payment is cancelled rather than left waiting for an event that will never come.
  update public.payments pay set status = 'cancelled' where pay.order_id = p_order_id and pay.status = 'pending';
  update public.orders o set status = 'completed', payment_status = 'not_required' where o.id = p_order_id;

  insert into public.entitlements (profile_id, book_id, source_type, source_order_id, status)
  values (v_profile_id, v_book_id, 'free_order', p_order_id, 'active')
  on conflict (profile_id, book_id) where status = 'active' do nothing
  returning id into v_entitlement_id;

  if v_entitlement_id is null then
    -- The reader already holds an active entitlement for this book, from an admin grant or another
    -- order that landed between this order's creation and now. Resolved by subject, the way
    -- acquire_free_ebook and apply_payment_event both resolve it.
    select e.id into v_entitlement_id
    from public.entitlements e
    where e.profile_id = v_profile_id and e.book_id = v_book_id and e.status = 'active';
  end if;

  insert into public.library_items (profile_id, book_id, entitlement_id)
  values (v_profile_id, v_book_id, v_entitlement_id)
  on conflict (profile_id, book_id) do nothing;

  update public.coupon_redemptions r
  set status = 'redeemed', redeemed_at = now()
  where r.order_id = p_order_id;

  return query select v_order.subtotal_minor, v_discount, 0::bigint, 'completed'::public.order_status,
                      v_entitlement_id, null::text, null::text;
end;
$$;

-- remove_coupon_from_order. Only ever reachable on a pending order that still has a coupon: a
-- zero-total order completed the moment its code was applied, so there is no window in which a
-- completed order can have its discount taken away.
create function public.remove_coupon_from_order(p_order_id uuid)
returns table (subtotal_minor bigint, discount_minor bigint, total_minor bigint)
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_profile_id uuid;
  v_order record;
begin
  select p.id into v_profile_id from public.profiles p where p.auth_user_id = auth.uid();
  if v_profile_id is null then
    raise exception 'remove_coupon_from_order: no profile for the current session' using errcode = 'P0002';
  end if;

  select o.id, o.status, o.subtotal_minor, o.coupon_id
  into v_order
  from public.orders o
  where o.id = p_order_id and o.profile_id = v_profile_id
  for update;
```

```ts
// codes cannot be enumerated by their error"). `detail` exists for the server log and nothing else -
// the Server Action writes it beside the request ID and shows the reader the one shared message.
export class CouponRejectedError extends Error {
  constructor(readonly detail: string | null) {
    super("This code cannot be used.");
    this.name = "CouponRejectedError";
  }
}

export class CouponRateLimitedError extends Error {
  constructor() {
    super("Too many codes have been tried.");
    this.name = "CouponRateLimitedError";
  }
}

// The ORDER refused the operation - not the caller's, not pending, already couponed, or already
// carrying a reported transfer. Distinct from CouponRejectedError because it sends the reader
// somewhere else rather than asking them to retype anything.
export class OrderNotCouponableError extends Error {
  constructor() {
    super("This order cannot take a code right now.");
    this.name = "OrderNotCouponableError";
  }
}

export type ApplyCouponResult = {
  subtotalMinor: number;
  discountMinor: number;
  totalMinor: number;
  completed: boolean;
  entitlementId: string | null;
};

type ApplyRow = {
  subtotal_minor: number;
  discount_minor: number;
  total_minor: number;
  order_status: string;
  entitlement_id: string | null;
  rejection: string | null;
  detail: string | null;
};

export async function applyCouponToOrder(locale: Locale, orderId: string, code: string): Promise<ApplyCouponResult> {
  await requireUser(locale);

  // A code that cannot exist is refused here, so a keyboard mash never reaches the database and
  // never spends a unit of the reader's own attempt quota.
  const normalized = normalizeCouponCode(code);
  if (!isCouponCode(normalized)) throw new CouponRejectedError("malformed code");

  const supabase = await createClient();
  const { data, error } = await supabase.rpc("apply_coupon_to_order", { p_order_id: orderId, p_code: normalized });
  if (error) {
    // EB024: the order, not the code. P0002: no profile for this session at all, which means the
    // same thing to the reader - this order is not theirs to change.
    if (error.code === "EB024" || error.code === "P0002") throw new OrderNotCouponableError();
    throw new Error(`applyCouponToOrder: apply_coupon_to_order failed: ${error.message}`);
  }

  const row = (data as ApplyRow[] | null)?.[0];
  if (!row) throw new Error("applyCouponToOrder: apply_coupon_to_order returned no row");
  if (row.rejection === "rate_limited") throw new CouponRateLimitedError();
  if (row.rejection !== null) throw new CouponRejectedError(row.detail);

  return {
    subtotalMinor: Number(row.subtotal_minor),
    discountMinor: Number(row.discount_minor),
    totalMinor: Number(row.total_minor),
    completed: row.order_status === "completed",
    entitlementId: row.entitlement_id,
  };
}

export async function removeCouponFromOrder(
  locale: Locale,
  orderId: string,
): Promise<{ subtotalMinor: number; discountMinor: number; totalMinor: number }> {
  await requireUser(locale);
  const supabase = await createClient();
  const { data, error } = await supabase.rpc("remove_coupon_from_order", { p_order_id: orderId });
  if (error) {
    if (error.code === "EB024" || error.code === "P0002") throw new OrderNotCouponableError();
    throw new Error(`removeCouponFromOrder: remove_coupon_from_order failed: ${error.message}`);
  }
  const row = (data as { subtotal_minor: number; discount_minor: number; total_minor: number }[] | null)?.[0];
  if (!row) throw new Error("removeCouponFromOrder: remove_coupon_from_order returned no row");
  return {
    subtotalMinor: Number(row.subtotal_minor),
    discountMinor: Number(row.discount_minor),
    totalMinor: Number(row.total_minor),
  };
}
```

```ts
"use server";

import { revalidatePath } from "next/cache";
import { headers } from "next/headers";
import { redirect } from "next/navigation";

import { requireUser } from "@/lib/auth/session";
import {
  CouponRateLimitedError,
  CouponRejectedError,
  OrderNotCouponableError,
  applyCouponToOrder,
  removeCouponFromOrder,
} from "@/lib/commerce/coupon-order";
import { getCustomerOrder } from "@/lib/data/orders";
import { defaultLocale, isLocale, withLocale } from "@/lib/i18n/config";
import { getCatalogRoutes, getCommerceRoutes } from "@/lib/i18n/routes";
import { getRequestId } from "@/lib/observability/request-id";

// Every runtime export below is an async function: a non-function export from a "use server" module
// builds cleanly and then crashes the client at request time.

// One state per message the checkout page can show (S8 spec 7.1). "invalid" covers every reason a
// code was refused, because saying which one is how a code space gets searched.
export type CouponFormState =
  | { status: "idle" }
  | { status: "applied" }
  | { status: "invalid" }
  | { status: "rateLimited" }
  | { status: "unavailable" };

// The discriminating reason goes here and nowhere else (spec 5.5).
async function logRejection(operation: string, orderId: string, detail: string | null): Promise<void> {
  console.warn("Coupon rejected.", { operation, orderId, detail, requestId: getRequestId(await headers()) });
}

export async function applyCouponAction(
  locale: string,
  orderId: string,
  _previous: CouponFormState,
  formData: FormData,
): Promise<CouponFormState> {
  if (!isLocale(locale)) redirect(withLocale(defaultLocale, "/"));
  const commerce = getCommerceRoutes(locale);
  await requireUser(locale, commerce.checkout(orderId));

  const code = String(formData.get("code") ?? "");

  let result;
  try {
    result = await applyCouponToOrder(locale, orderId, code);
  } catch (error) {
    if (error instanceof CouponRateLimitedError) return { status: "rateLimited" };
    if (error instanceof CouponRejectedError) {
      await logRejection("applyCouponAction", orderId, error.detail);
      return { status: "invalid" };
    }
    if (error instanceof OrderNotCouponableError) return { status: "unavailable" };
    throw error;
  }

  revalidatePath(commerce.checkout(orderId));

  // A fully discounted order completed inside the RPC (spec 5.4), so there is nothing left to pay
  // and the book is already in the reader's library. The book id comes from the order rather than
  // from the RPC, which returns the entitlement.
  if (result.completed) {
    const order = await getCustomerOrder(orderId);
    if (order) redirect(getCatalogRoutes(locale).read(order.bookId));
    redirect(commerce.checkoutStatus(orderId));
  }

  return { status: "applied" };
}

export async function removeCouponAction(
  locale: string,
  orderId: string,
  _previous: CouponFormState,
  _formData: FormData,
): Promise<CouponFormState> {
  if (!isLocale(locale)) redirect(withLocale(defaultLocale, "/"));
  const commerce = getCommerceRoutes(locale);
  await requireUser(locale, commerce.checkout(orderId));

  try {
    await removeCouponFromOrder(locale, orderId);
  } catch (error) {
    if (error instanceof OrderNotCouponableError) return { status: "unavailable" };
    throw error;
  }

  revalidatePath(commerce.checkout(orderId));
  return { status: "idle" };
}
```

```tsx
"use client";

import { useActionState } from "react";

import type { CouponFormState } from "@/app/[locale]/(account)/checkout/[orderId]/coupon-actions";
import { SubmitButton } from "@/components/auth/submit-button";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";
import { fillTemplate } from "@/lib/i18n/format";

type Copy = {
  legend: string;
  label: string;
  apply: string;
  applying: string;
  remove: string;
  removing: string;
  subtotal: string;
  discount: string;
  applied: string;
  invalid: string;
  rateLimited: string;
  unavailable: string;
};

type Action = (state: CouponFormState, formData: FormData) => Promise<CouponFormState>;

const initial: CouponFormState = { status: "idle" };

// The reader's code field (S8 spec 7.1). A code that is already on the order is not editable: it is
// removed and a different one entered, which is also what keeps "one coupon per order" true without
// the UI having to know anything about reservations.
export function CouponForm({
  appliedCode,
  applyAction,
  copy,
  removeAction,
}: {
  appliedCode: string | null;
  applyAction: Action;
  copy: Copy;
  removeAction: Action;
}) {
  const [applyState, apply] = useActionState(applyAction, initial);
  const [removeState, remove] = useActionState(removeAction, initial);
  const message =
    applyState.status === "invalid"
      ? copy.invalid
      : applyState.status === "rateLimited"
        ? copy.rateLimited
        : applyState.status === "unavailable" || removeState.status === "unavailable"
          ? copy.unavailable
          : null;

  return (
    <section aria-label={copy.legend} className="mt-6 border-t border-hairline pt-6">
      {appliedCode ? (
        <div className="flex flex-wrap items-center justify-between gap-3">
          <p role="status">{fillTemplate(copy.applied, { code: appliedCode })}</p>
          <form action={remove}>
            <SubmitButton pendingLabel={copy.removing}>{copy.remove}</SubmitButton>
          </form>
        </div>
      ) : (
        <form action={apply} className="flex flex-col gap-3 sm:flex-row sm:items-end">
          <div className="min-w-0 flex-1 space-y-2">
            <Label htmlFor="coupon-code">{copy.label}</Label>
            <Input autoCapitalize="characters" autoComplete="off" className="min-h-11" id="coupon-code" name="code" spellCheck={false} />
          </div>
          <SubmitButton className="min-h-11" pendingLabel={copy.applying}>
            {copy.apply}
          </SubmitButton>
        </form>
      )}
      {message ? (
        <p className="mt-3 text-sm text-error" role="alert">
          {message}
        </p>
      ) : null}
    </section>
  );
}
```

```sql
-- S8: the operator's coupon surface (spec 7.2).
--
-- New error code, continuing the EB0xx series (EB024 is taken by 20260923120000):
--   EB025 - admin_update_coupon: the kind or value of a coupon that already has a reservation or a
--           redemption cannot change.
--
-- Why these are RPCs and not table policies. coupons has no select policy at all and no grants:
-- that is what makes a code impossible to enumerate through PostgREST, by a reader and by an admin
-- alike. The admin screens read through these definer functions instead, which return exactly the
-- columns those screens render.

create function public.admin_list_coupons()
returns table (
  id uuid, code text, kind text, percent_off int, amount_off_minor bigint, currency text,
  starts_at timestamptz, ends_at timestamptz, active boolean, max_redemptions int,
  max_redemptions_per_profile int, note text, created_at timestamptz,
  reserved_count bigint, redeemed_count bigint, book_ids uuid[]
)
language plpgsql
security definer
set search_path = ''
as $$
begin
  if not public.is_admin() then
    raise exception 'admin_list_coupons: caller is not an admin' using errcode = '42501';
  end if;

  return query
  select c.id, c.code, c.kind, c.percent_off, c.amount_off_minor, c.currency,
         c.starts_at, c.ends_at, c.active, c.max_redemptions,
         c.max_redemptions_per_profile, c.note, c.created_at,
         coalesce(count(r.id) filter (where r.status = 'reserved'), 0),
         coalesce(count(r.id) filter (where r.status = 'redeemed'), 0),
         coalesce((select array_agg(cb.book_id order by cb.book_id) from public.coupon_books cb where cb.coupon_id = c.id), '{}'::uuid[])
  from public.coupons c
  left join public.coupon_redemptions r on r.coupon_id = c.id
  group by c.id
  order by c.created_at desc
  limit 200;
end;
$$;

  p_kind text,
  p_percent_off int,

  p_note text,
  p_book_ids uuid[]

declare
  v_admin_id uuid;
  v_code text;
  v_id uuid;

  -- who pastes " tester-100 " creates the code a reader entering "TESTER-100" will find.

  -- a message the editor can show against the right field.

-- The code itself is never editable: a reader may already be holding it on a slip of paper, and a
-- renamed code is a different promotion. Kind and value become read-only once the coupon has been
-- reserved or redeemed even once (spec 7.2) - changing the value of a code readers have already
-- committed to would change an order snapshot after the fact. Window, activity, limits, note, and
-- book scope stay editable throughout, which is what "deactivate" and "shorten the window" need.
create function public.admin_update_coupon(
  p_id uuid,
  p_kind text,
  p_percent_off int,
  p_amount_off_minor bigint,
  p_currency text,
  p_starts_at timestamptz,
  p_ends_at timestamptz,
  p_active boolean,
  p_max_redemptions int,
  p_max_redemptions_per_profile int,
  p_note text,
  p_book_ids uuid[]
)
returns void
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_admin_id uuid;
  v_coupon record;
  v_locked boolean;
  v_changes_value boolean;
begin
  if not public.is_admin() then
    raise exception 'admin_update_coupon: caller is not an admin' using errcode = '42501';
  end if;
  select pr.id into v_admin_id from public.profiles pr where pr.auth_user_id = auth.uid();

  select c.* into v_coupon from public.coupons c where c.id = p_id for update;
  if v_coupon.id is null then
    raise exception 'admin_update_coupon: coupon % does not exist', p_id using errcode = 'P0002';
  end if;

  select exists (select 1 from public.coupon_redemptions r where r.coupon_id = p_id) into v_locked;
  v_changes_value :=
    p_kind is distinct from v_coupon.kind
    or (p_kind = 'percent' and p_percent_off is distinct from v_coupon.percent_off)
    or (p_kind = 'fixed' and (p_amount_off_minor is distinct from v_coupon.amount_off_minor
                              or upper(coalesce(p_currency, '')) is distinct from v_coupon.currency));

  if v_locked and v_changes_value then
    raise exception 'admin_update_coupon: coupon % is already reserved or redeemed', p_id using errcode = 'EB025';
  end if;

  update public.coupons c
  set kind = p_kind,
      percent_off = case p_kind when 'percent' then p_percent_off else null end,
      amount_off_minor = case p_kind when 'fixed' then p_amount_off_minor else null end,
      currency = case p_kind when 'fixed' then upper(p_currency) else null end,
      starts_at = p_starts_at,
      ends_at = p_ends_at,
      active = coalesce(p_active, true),
      max_redemptions = p_max_redemptions,
      max_redemptions_per_profile = coalesce(p_max_redemptions_per_profile, 1),
      note = nullif(btrim(coalesce(p_note, '')), '')
  where c.id = p_id;

  delete from public.coupon_books cb
  where cb.coupon_id = p_id and cb.book_id <> all (coalesce(p_book_ids, '{}'::uuid[]));
  insert into public.coupon_books (coupon_id, book_id)
  select p_id, b from unnest(coalesce(p_book_ids, '{}'::uuid[])) as b
  on conflict do nothing;

  insert into public.audit_logs (actor_profile_id, action, entity_type, entity_id, reason, metadata)
  values (v_admin_id, 'coupon.updated', 'coupons', p_id, null,
          jsonb_build_object('active', coalesce(p_active, true), 'starts_at', p_starts_at, 'ends_at', p_ends_at,
                             'max_redemptions', p_max_redemptions,
                             'max_redemptions_per_profile', coalesce(p_max_redemptions_per_profile, 1),
                             'book_ids', coalesce(p_book_ids, '{}'::uuid[])));
end;
$$;

revoke execute on function public.admin_list_coupons() from public, anon;
grant execute on function public.admin_list_coupons() to authenticated;
revoke execute on function public.admin_get_coupon(uuid) from public, anon;
```

```ts
import "server-only";

import { requireAdmin } from "@/lib/auth/admin";
import type { CouponInput } from "@/lib/catalog/schemas";
import type { CouponKind } from "@/lib/commerce/coupon";
import { createClient } from "@/lib/supabase/server";

export type AdminCouponDTO = {
  id: string;
  code: string;
  kind: CouponKind;
  percentOff: number | null;
  amountOffMinor: number | null;
  currency: string | null;
  startsAt: string | null;
  endsAt: string | null;
  active: boolean;
  maxRedemptions: number | null;
  maxRedemptionsPerProfile: number;
  note: string | null;
  createdAt: string;
  // Reserved is "held by a pending order"; redeemed is "spent". Together they are the whole
  // reporting surface S8 has (spec 3).
  reservedCount: number;
  redeemedCount: number;
  bookIds: string[];
};

type CouponRow = {
  id: string; code: string; kind: CouponKind; percent_off: number | null; amount_off_minor: number | null;
  currency: string | null; starts_at: string | null; ends_at: string | null; active: boolean;
  max_redemptions: number | null; max_redemptions_per_profile: number; note: string | null;
  created_at: string; reserved_count: number; redeemed_count: number; book_ids: string[] | null;
};

// EB025 is surfaced as a named condition rather than swallowed: the editor tells the operator why
// the value did not change instead of showing a generic failure.
export class CouponValueLockedError extends Error {
  constructor() {
    super("This coupon has already been used, so its value cannot change.");
    this.name = "CouponValueLockedError";
  }
}

function toDTO(row: CouponRow): AdminCouponDTO {
  return {
    id: row.id,
    code: row.code,
    kind: row.kind,
    percentOff: row.percent_off,
    amountOffMinor: row.amount_off_minor === null ? null : Number(row.amount_off_minor),
    currency: row.currency,
    startsAt: row.starts_at,
    endsAt: row.ends_at,
    active: row.active,
    maxRedemptions: row.max_redemptions,
    maxRedemptionsPerProfile: row.max_redemptions_per_profile,
    note: row.note,
    createdAt: row.created_at,
    reservedCount: Number(row.reserved_count),
    redeemedCount: Number(row.redeemed_count),
    bookIds: row.book_ids ?? [],
  };
}

// coupons has no select policy at all, by design (spec 5.2), so every read here goes through a
// definer RPC rather than through PostgREST.
export async function listAdminCoupons(): Promise<AdminCouponDTO[]> {
  await requireAdmin();
  const supabase = await createClient();
  const { data, error } = await supabase.rpc("admin_list_coupons");
  if (error) throw new Error(`listAdminCoupons: admin_list_coupons failed: ${error.message}`);
  return ((data ?? []) as CouponRow[]).map(toDTO);
}

export async function getAdminCoupon(couponId: string): Promise<AdminCouponDTO | null> {
  await requireAdmin();
  const supabase = await createClient();
  const { data, error } = await supabase.rpc("admin_get_coupon", { p_id: couponId });
  if (error) throw new Error(`getAdminCoupon: admin_get_coupon failed: ${error.message}`);
  const row = (data as CouponRow[] | null)?.[0];
  return row ? toDTO(row) : null;
}

function rpcArguments(input: CouponInput) {
  return {
    p_kind: input.kind,
    p_percent_off: input.percentOff,
    p_amount_off_minor: input.amountOffMinor,
    p_currency: input.currency,
    p_starts_at: input.startsAt,
    p_ends_at: input.endsAt,
    p_max_redemptions: input.maxRedemptions,
    p_max_redemptions_per_profile: input.maxRedemptionsPerProfile,
    p_note: input.note,
    p_book_ids: input.bookIds,
  };
}

export async function createCoupon(input: CouponInput): Promise<string> {
  await requireAdmin();
  const supabase = await createClient();
  const { data, error } = await supabase.rpc("admin_create_coupon", { p_code: input.code, ...rpcArguments(input) });
  if (error) {
    // 23505: the unique index on coupons.code. Re-thrown with the code intact so the action can
    // show it against the code field instead of as a generic failure.
    if (error.code === "23505") throw new Error("createCoupon: duplicate code (23505)");
    throw new Error(`createCoupon: admin_create_coupon failed: ${error.message}`);
  }
  return data as string;
}

export async function updateCoupon(couponId: string, input: CouponInput): Promise<void> {
  await requireAdmin();
  const supabase = await createClient();
  const { error } = await supabase.rpc("admin_update_coupon", { p_id: couponId, p_active: input.active, ...rpcArguments(input) });
  if (error) {
    if (error.code === "EB025") throw new CouponValueLockedError();
    throw new Error(`updateCoupon: admin_update_coupon failed: ${error.message}`);
  }
}
```

```ts
"use server";

import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";

import { requireAdmin } from "@/lib/auth/admin";
import {
  fieldErrorsFrom,
  readBoolean,
  readInteger,
  readList,
  readOptionalInteger,
  readOptionalText,
  readText,
  type AdminFormState,
} from "@/lib/catalog/form";
import { couponSchema } from "@/lib/catalog/schemas";
import { CouponValueLockedError, createCoupon, updateCoupon } from "@/lib/data/coupons";

const genericFailure = "Something went wrong saving. Try again.";
const duplicateFailure = "That code already exists.";

function parse(formData: FormData) {
  return couponSchema.safeParse({
    code: readText(formData, "code"),
    kind: readText(formData, "kind"),
    percentOff: readOptionalInteger(formData, "percentOff"),
    amountOffMinor: readOptionalInteger(formData, "amountOffMinor"),
    currency: readOptionalText(formData, "currency")?.toUpperCase() ?? null,
    startsAt: readOptionalText(formData, "startsAt"),
    endsAt: readOptionalText(formData, "endsAt"),
    active: readBoolean(formData, "active"),
    maxRedemptions: readOptionalInteger(formData, "maxRedemptions"),
    maxRedemptionsPerProfile: readInteger(formData, "maxRedemptionsPerProfile") ?? 1,
    note: readOptionalText(formData, "note"),
    bookIds: readList(formData, "bookIds"),
  });
}

export async function createCouponAction(_previous: AdminFormState, formData: FormData): Promise<AdminFormState> {
  await requireAdmin({ next: "/admin/coupons/new" });

  const parsed = parse(formData);
  if (!parsed.success) return { fieldErrors: fieldErrorsFrom(parsed.error), formError: null, savedAt: null };

  let couponId: string;
  try {
    couponId = await createCoupon(parsed.data);
  } catch (error) {
    // The operator retypes a code rather than reading a generic failure and wondering what broke.
    if (String(error).includes("23505")) {
      return { fieldErrors: { code: duplicateFailure }, formError: null, savedAt: null };
    }
    return { fieldErrors: {}, formError: genericFailure, savedAt: null };
  }

  revalidatePath("/admin/coupons");
  redirect(`/admin/coupons/${couponId}`);
}

export async function updateCouponAction(
  couponId: string,
  _previous: AdminFormState,
  formData: FormData,
): Promise<AdminFormState> {
  await requireAdmin({ next: `/admin/coupons/${couponId}` });

  const parsed = parse(formData);
  if (!parsed.success) return { fieldErrors: fieldErrorsFrom(parsed.error), formError: null, savedAt: null };

  try {
    await updateCoupon(couponId, parsed.data);
  } catch (error) {
    if (error instanceof CouponValueLockedError) {
      return { fieldErrors: {}, formError: error.message, savedAt: null };
    }
    return { fieldErrors: {}, formError: genericFailure, savedAt: null };
  }

  revalidatePath("/admin/coupons");
  revalidatePath(`/admin/coupons/${couponId}`);
  return { fieldErrors: {}, formError: null, savedAt: Date.now() };
}
```
